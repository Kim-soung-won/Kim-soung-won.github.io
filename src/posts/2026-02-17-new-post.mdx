네트워크 계층(Network Layer)은 단순히 데이터를 전달하는 것 이상의 복잡한 메커니즘을 내포하고 있습니다. 크게 **제어 평면(Control Plane)**과 **데이터 평면(Data Plane)**으로 나누어 이해할 수 있습니다.

- **제어 평면 (Control Plane)**: "어떤 경로로 가야 할까?"를 고민하는 **두뇌** 영역. (라우팅 알고리즘)
- **데이터 평면 (Data Plane)**: "이 패킷을 3번 포트로 보내!"라고 실제로 행동하는 **근육** 영역. (패킷 포워딩)

이 글에서는 먼저 IP 주소 체계와 서브넷팅을 간단히 짚고, 라우터 내부의 하드웨어적인 동작(데이터 평면)에 대해 깊이 있게 다뤄보겠습니다.

---

## 1. 네트워크 계층의 기본: IP와 서브넷팅

데이터 평면을 이해하기 전에, 라우터가 무엇을 보고 판단하는지 알아야 합니다. 바로 **IP 주소**입니다.

<Callout type="info" title="IP 주소와 CIDR">
  과거에는 클래스(A, B, C) 단위로 주소를 나눴지만, 현재는 **CIDR (Classless Inter-Domain Routing)** 방식을 사용합니다.
  
  예: `192.168.1.0/24`
  - 앞 24비트 (`192.168.1`)는 **네트워크 ID**
  - 뒤 8비트 (`.0` ~ `.255`)는 **호스트 ID**
</Callout>

### 서브넷팅 (Subnetting)의 마법

하나의 네트워크를 더 작은 단위로 쪼개는 기술입니다.

<Steps>
  <Step title="네트워크 확보">
    `192.168.10.0/24` 네트워크를 할당받았다고 가정합시다. 총 256개의 주소(0~255)를 사용할 수 있습니다.
  </Step>
  <Step title="서브넷 분할">
    이를 4개의 부서(인사, 개발, 영업, 기획)로 나누고 싶다면, 호스트 비트에서 2비트를 빌려옵니다. (`2^2 = 4`)
    
    새로운 서브넷 마스크는 `/26` (`255.255.255.192`)이 됩니다.
  </Step>
  <Step title="결과">
    각 부서는 64개의 IP 대역을 갖게 됩니다.
    - 인사: `192.168.10.0/26`
    - 개발: `192.168.10.64/26` ...
  </Step>
</Steps>

## 2. 데이터 평면(Data Plane): 네트워크의 근육

네트워크 계층의 데이터 평면은 네트워크의 ‘근육’과 같습니다. 복잡한 길 찾기(라우팅)은 제어평면이 고민하게 두고 실제로 패킷 하나하나 집어서 올바른 통로로 던져주는 실무는 모두 데이터 평면에서 이뤄집니다.

> 데이터 평면을 이해하기 위한 핵심 키워드는 **매치-플러스-액션(Match-Plus-Action)**입니다.

### 2-1. 데이터 평면의 핵심: 포워딩

데이터 평면이 하는 일은 단순하지만 매우 빨라야합니다. 라우터에 패킷이 도착하면 딱 두 단계만 거칩니다.

1.  **매치(Match)**: 패킷 헤더의 정보를 보고 “너는 누구니? 어디로 가니?”를 확인해야합니다.
2.  **액션(Action)**: “3번 포트로 나가면 돼~”, 혹은 “너는 차단된 패킷이니 버릴게” 같은 행동을 수행합니다.

이 규칙들이 적힌 장부를 **포워딩 테이블**이라고 칭합니다.

### 2-2. 라우터 하드웨어 속의 데이터 평면

패킷이 라우터 내부에서 이동하는 경로는 아주 정교한 하드웨어 설계의 결과물입니다.

  <FolderItem name="Router Structure" defaultOpen>
    <FileItem name="Input Port (Inspection)" />

1.  **입력 포트 - 검문소**
    패킷이 들어오자마자 하는 일은 포워딩 테이블을 검색하는 것입니다.
    -   **속도가 생명**: 수 나노초 안에 결정을 내려야 하므로, 일반 메모리가 아닌 **TCAM**이라는 특수 고속 메모리를 사용하기도 합니다.
    -   여기서 결정된 출력 포트로 패킷을 넘깁니다.

2.  **스위칭 패브릭(Switching Fabric) - 고속도로**
    입력포트에서 출력포트로 패킷을 실제로 옮겨주는 장치입니다. 세가지 방식이 존재합니다.
    -   **메모리 방식**: CPU가 직접 옮김 (예전의 방식으로 느림)
    -   **버스 방식**: 하나의 통로를 공유함 (한 번에 하나씩만 이동 가능)
    -   **크로스바 방식**: 여러 통로를 격자 형태로 연결 (여러 패킷이 동시에 이동 가능, 현대 고성능 라우터 방식)

3.  **출력 포트 - 대기실**
    패킷이 나가기 직전에 머무는 곳입니다. 만약 나가는 길보다 들어오는 패킷이 더 많으면 여기서 **큐잉(Queuing)**이 발생하고, 자리가 없으면 패킷을 버리게 됩니다. (**Packet Loss**)

### 2-3. 일반화된 포워딩과 SDN

전통적인 라우터는 오직 목적지 IP주소만 보고 포워딩을 했습니다. 하지만 현대의 **SDN(Software Defined Networking)** 환경에서는 훨씬 똑똑해졌습니다.

-   **다양한 매치**: IP 주소뿐만 아니라, MAC 주소, 포트번호 등을 모두 조합해서 매치할 수 있습니다.
-   **다양한 액션**: 단순히 내보내는 것뿐만 아니라, 패킷의 내용을 수정하거나(NAT), 특정 서버로 복사본을 보내는 작업도 가능합니다.

과거의 데이터 평면은 주소를 갖고 패킷을 분류했다면 오늘날에는 보다 복잡한 판단을 내리고 더 최적화된 행동을 수행합니다.

### 2-4. 하드웨어의 발전

초창기 라우터는 일반 PC와 동일했습니다. CPU가 패킷을 하나하나 읽어서 처리했습니다. 하지만 인터넷 트래픽이 폭발하면서 소프트웨어 방식으로는 도저히 속도를 감당할 수 없게 되었습니다.

그래서 엔지니어들은 포워딩 로직을 아예 **ASIC 칩**으로 구워버렸습니다. 이것이 데이터 평면을 소프트웨어가 아닌 하드웨어 영역으로 부르는 이유입니다. 소프트웨어의 영역(제어 평면)과 하드웨어의 영역(데이터 평면)을 나눠 더 빠르게 한 것입니다.

## 3. 소프트웨어 개발자는 손쓸 부분이 없는 계층인가?

거의 맞는 말입니다. 네트워크 계층의 90%는 일반적인 애플리케이션 개발자가 관여하지 않는 영역입니다. 하지만 나머지 10%영역에서 그 역량이 갈리기도 합니다.

네트워크 계층의 철학은 **중간은 최대한 단순하게(Dumb), 양 끝단은 똑똑하게(Smart)이다.** 이를 **종단 간 원칙(End-to-End Principle)**이라고 칭합니다.

<ProsCons>
  <Pros title="개발자가 이해해야 할 영역">
    - **OS의 추상화**: IP주소를 할당하고 패킷에 헤더를 붙이는 작업은 전적으로 운영체제의 커널이 전담합니다. 개발자는 소켓에 데이터만 던질 뿐입니다.
    - **클라우드 인프라**: 현대 개발자는 클라우드 환경에서 VPC, Subnet, 라우팅 테이블을 직접 설정해야 합니다. 이때 네트워크 계층의 동작을 이해해야 합니다.
  </Pros>
  <Cons title="개발자가 할 수 없는 영역">
    - **하드웨어 처리**: 데이터 평면의 처리는 라우터 내부의 **ASIC**이 처리합니다. 소프트웨어가 이를 제어하기에는 인터넷 트래픽이 너무 빠릅니다.
  </Cons>
</ProsCons>

### 성능 최적화와 패킷 크기 (MTU/MSS)

네트워크 계층에는 한 번에 보낼 수 있는 최대크기인 **MTU**가 있습니다.

-   개발자가 보낸 데이터가 너무 크면 네트워크 계층에서 패킷이 쪼개집니다.
-   이는 라우터에 부담을 주고 지연 시간을 늘립니다. 고성능 통신 프로그램을 짤 때는 이 크기를 고려해서 애플리케이션 버퍼를 설계해야합니다.

### 보안과 방화벽 (ACL)

특정 IP 대역만 허용하거나 차단하는 설정은 네트워크 계층의 작업입니다. 통신이 원활하지 않을때, 이게 네트워크 계층의 IP 화이트리스트 문제임을 이해해야합니다.
